# GEMINI Project Guidelines & Architecture: Manipulator3

## 1. Суть проекта и Архитектура

### 1.1 Суть проекта
Автономная 6-DOF рука-манипулятор с клешневым захватом, функционирующая на плоской поверхности стола.
Задача системы:
1. Распознать жест указания пальцем человека на стол (даже если целевой объект изначально находится вне поля зрения камеры манипулятора).
2. Спроецировать направление указания на плоскость стола и развернуть манипулятор для сканирования целевого сектора.
3. Обнаружить объект с помощью камеры на клешне (OV5647) и нейросети YOLO11n.
4. Выполнить точное сближение, контролируя расстояние до объекта с помощью лазерного дальномера VL53L0X, установленного параллельно плоскости сжатия клешни.
5. Захватить объект клешней, поднять и переместить его в зону выгрузки на столе возле основания манипулятора.

### 1.3 Аппаратный стек и распиновка Thin Client (Raspberry Pi Zero W)

#### Приводы (Actuators)
* **Поворотное основание (Azimuth Base):** Шаговый двигатель **NEMA 17** под управлением драйвера **A4988**:
  * `STEP` $\rightarrow$ **GPIO 17**
  * `DIR` $\rightarrow$ **GPIO 27**
* **Суставы и клешня (6x PWM Servos):**
  * `Servo 1 (Талия / Shoulder A)` — **MG996R** $\rightarrow$ **GPIO 26**
  * `Servo 2 (Талия / Shoulder B)` — **MG996R** $\rightarrow$ **GPIO 19** *(Pin 35, Внимание: механический реверс движения относительно Servo 1, роторы расположены оппозитно)*
  * `Servo 3 (Локоть / Elbow)` — **MG996R** $\rightarrow$ **GPIO 13**
  * `Servo 4 (Запястье / Wrist Pitch)` — **MG996R** $\rightarrow$ **GPIO 6**
  * `Servo 5 (Вращение клешни / Wrist Roll)` — **MG90S** $\rightarrow$ **GPIO 5**
  * `Servo 6 (Сжатие клешни / Gripper Jaw)` — **MG90S** $\rightarrow$ **GPIO 22**

#### Сенсоры (Sensors)
* **Лазерный дальномер VL53L0X (I2C):**
  * `SDA` $\rightarrow$ **GPIO 2**
  * `SCL` $\rightarrow$ **GPIO 3**
* **Зрение:** **Raspberry Pi Camera (OV5647)** $\rightarrow$ интерфейс **MIPI CSI** (ленточный шлейф RPi Zero).

## 2. Ключевые Правила Разработки (Mandatory Rules)

1. **Только один этап за один запрос:**
   - Строго запрещено выполнять несколько этапов плана одновременно.
   - За один запрос реализуется ровно один этап плана из `PLAN.md`.
2. **Тестирование только критических участков:**
   - Покрывать тестами (`pytest`) только необходимую логику: математику прямой и обратной кинематики (IK), расчет пересечения луча с плоскостью стола, сериализацию сообщений Zenoh и программные лимиты безопасности.
   - Не писать избыточных тестов на тривиальный код и внешние библиотеки.
3. **Минималистичные комментарии к коду:**
   - Оставлять краткие комментарии только в неочевидных местах или там, где ранее была допущена ошибка.
   - Не загромождать понятный код очевидными комментариями.
4. **Лаконичный логгинг без длинных инструкций:**
   - Логировать только критические события и состояния (`INFO`/`WARNING`/`ERROR`).
   - Все логи писать кратко и строго на английском языке (например: `[INFO] Target acquired at (x, y, z)`).
   - Не печатать в консоли длинные мануалы и инструкции по использованию.
5. **Git Push после каждого выполненного этапа:**
   - По завершении каждого этапа плана выполнить коммит с осмысленным сообщением и сделать `git push origin main`.
6. **Никаких лишних абстракций:**
   - Писать прямой, чистый и прагматичный код.
   - Использовать простые модули и функции. Не создавать фабрики фабрик, сложные наследования и абстрактные обертки там, где достаточно прямой функции или компактного класса.
7. **Чеклист для пользователя:**
   - После завершения каждого этапа предоставлять пользователю четкий список шагов для проверки.
